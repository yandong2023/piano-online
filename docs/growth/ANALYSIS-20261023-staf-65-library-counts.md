## 3. 推断层（标置信度 + 反证条件）

**I1（高）本单是体验/信任修复，不是增长杠杆。**
能触达的上限就是曲库首页 38 用户/28 天 + moonlight 页 6 用户/28 天。即便用户看到正确计数后体验改善，任何指标变化都小于当前数据的日间波动（曲库页日浏览 5–18 波动），不可能在本周数据里被识别。
*反证条件*：若曲库页日流量在 10-19 之后持续爬升（例如 STAF-64 内链生效带来自然搜索），影响面会随之放大，届时值得重算基线。

**I2（中）曲库首页「10-19 才有流量」与 STAF-64/STAF-63 的上线时间接近，但不能归因。**
同期至少有三件事在变（内链织网、音频预载、GSC 收录变化），属于「相关不等于因果」的典型场景。要判断得看 GSC 页面级曝光的时间序列，而不是 GA4 的 34 个用户。

**I3（中）曲库页人均参与 25 秒偏低，可能与本次修的「计数与卡片不一致」有关，但无证据。**
计数错乱会让用户不信任筛选结果而直接离开；也可能只是这类索引页天然是跳板页。现有事件无法区分「看了就走」与「筛了没找到」。
*反证条件*：补上筛选/搜索结果数事件后，看「筛选后是否有结果」与「是否进入歌曲页」的关系。

**I4（低）moonlight 教程映射修好后，短期内不会有可测变化。**
目标文 28 天仅 18 曝光 / 0 点击；月光页本身 19 曝光。这项修复的价值是「不再把自己的用户导向主题不符的文章」（信任与相关性），而不是带来流量。

## 4. 建议层

1. **本单不设独立观测窗口**（与产品验收结论一致）。理由：发布后无完整天数据、影响面 <1.1% 用户、且无可度量事件。相关口径已固定在本文第 1 节，后续曲库类改动直接复用。
2. **补埋点**（见第 5 节需求提案）——这是本单真正的运营侧产出：不是「指标涨了没」，而是「这类改动以后能不能被度量」。
3. **对产品提出的三条残留风险给优先级意见**（不新增需求，供 Morgan 判断）：
   - `js/library-browser.js` 对 `.song-category-heading > span` 无空值保护 → 后果是整页筛选失效，**建议 P3，随下一批做**（改动小、失败后果大）。
   - 英文 `1 songs` 单复数 → **并入下次英文文案整理，不单独发版**。
   - 隐藏分类标题保留 SSR 旧值、依赖 `css/studio.css` 的 `[hidden]{display:none!important}` → **建议只加一行注释说明依赖，顺带做**。
4. **曲库页的搜索入口问题不属本单**（GSC 28 天 `/songs/` 4 曝光、`/en/songs/` 40 曝光且位置 20.7），这属于 STAF-64 的内链与 SEO 议题，在 STAF-64 的观察窗口里一起看。

## 5. 需求提案（交 Morgan 转产品）

> 一条提案只讲一件事。

**现象**：曲库页的筛选（难度/搜索/分类按钮）与歌曲页「相关教程」链接没有埋点，任何这类改动上线后都无法判断用户有没有用、有没有因此改善。

**数据证据**：
- 曲库首页 28 天事件只有 `page_view`/`user_engagement`/`scroll`/`session_start`/`first_visit`；全站 14 天事件清单中无筛选、搜索、分类点击、教程点击事件（口径：GA4 property 469040246，28 天 = 2026-09-25~10-22，事件名维度）。
- `#difficulty` 深链在 `pageLocation` 中出现 0 次，深链入口不可还原。

**影响量级**：曲库首页 28 天 38 个用户（占全站 1.06%）；moonlight 页 28 天 6 个用户。**当前量级小，但这是「所有曲库类改动的可度量性底座」缺失，不是单次损失。**

**建议做法**（一个可交付的变化）：给曲库页加 3 个 GA4 事件——`library_filter_apply`（参数：`filter_type` = difficulty/category/search、`filter_value`、`result_count`）、`library_song_click`（参数：`song_id`、`position`）、`related_tutorial_click`（参数：`source_song_id`、`target_slug`）。不加参数就再等一年也无法回答「筛选后有没有结果」。

**优先级建议**：P3（现流量小），**触发升级条件**：曲库页周活用户连续 2 周 > 100，或 STAF-64 内链生效后 `/songs/` GSC 周曝光 > 200 → 升 P2。

**验证方式**：埋点上线后 2 周，看 `library_filter_apply/result_count` 中 `result_count = 0` 的占比（>20% 说明筛选/搜索体验有坑）与 `library_song_click` 的点击率。
