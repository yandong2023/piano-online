# STAF-64 技术方案 v1

对应 PRD：STAF-64 issue 描述，2026-10-22，AC-A / AC-B。基线 main f54622f：100 首公开歌曲、357 个 sitemap URL。任务所称 101 首与主线数据不一致，原因不确定；本轮不新增曲目或页面。

## 方案

采用修改现有生成器、构建时生成 FAQ 和静态内链的方案，所有文字可在 HTML 中读取。未采用浏览器运行后注入文字/内链：首屏及搜索抓取不可靠；未采用手工修改生成 HTML：重建会覆盖。

推荐按同难度、同作曲家（非空）、同分类、id 码点稳定顺序排序。先预留 3 首同难度曲目，其余候选取前 6 首为相关曲目，保证两个区块不重复，且最高难度只有 7 首时仍能输出 9 个不同目标。作曲家匹配沿用数据的完整 composer 字段。

难度入口使用现有曲库的 `#difficulty-1` 至 `#difficulty-4`，增加对应筛选控件和 hash 初始化/切换；不新增页面 URL 或 sitemap 项。教程映射固定写在歌曲生成器，slug 必须存在于教程数据。简/英分别指向已有页面；繁体没有独立教程页面，遵循任务“不存在则不渲染”，不造 URL、不跨语言回退。语言切换器原有跨语言链接不属于新增内容内链。

## 影响面

接口/迁移/权限/多租户/异步任务：无。数据：公开歌曲只读，新增静态映射及首页 FAQ 文案；无用户数据变化。缓存：不改 vercel.json。第三方：原样带入用户本地两行 GA4，不改变标识。修改只在独立 worktree 分支，不碰用户主工作区及任务禁止文件。

## 变更清单

- `scripts/studio-pages.mjs`：首页三语元信息、lead、本地化 FAQ 与独立 FAQPage JSON-LD；非首页保留原文。
- `css/home-faq.css`：只作用新增 FAQ。
- `scripts/render-song-pages.mjs`：6 首相关推荐、3 首同难度、教程映射、筛选入口、保留 GA4。
- `js/library-browser.js`：难度筛选/hash，与现有搜索和分类组合。
- `css/song-pages.css`：难度控件样式。
- `tests/homepage-static.test.mjs`、`tests/song-library.test.mjs`：适配标题并验证排序/本地化/去重/筛选。
- `scripts/verify-seo.mjs`：构建产物校验、抽样内链 HTTP 请求及证据输出。
- 现有受版本控制的生成页由生成器重建；不纳入基线原本未跟踪的数百个生成页。

## 测试点

AC-A：三语关键词、标题/description 长度、保留 H1/导航/hreflang、FAQ HTML 与 JSON-LD 一致；元信息前后对照。AC-B：全 300 首歌曲页各 9 个唯一曲目目标，固定种子抽 5 页；映射教程存在、同语言；30 URL 在本地 dist 服务实际 HTTP 200；sitemap 与基线逐项一致/357；两次构建内容哈希和 git diff 一致。执行 npm test、npm run build，保留日志；难度筛选用 DOM 运行测试覆盖无效 hash、组合搜索和重置。

## 上线与回滚

本任务只推分支/开 PR，交质检，不部署、不合并。获准发布时按既有静态站流程执行。回滚采用 `git revert <本 PR merge commit>` 后重新构建/发布，无数据迁移，可逆。

## 风险与未知

- Google 对标题的点击率和排名变化不确定，保留“在线钢琴”、H1 和原英文标题；上线后需运营观察。
- FAQPage 提供有效结构化数据，不承诺搜索引擎展示富结果。
- 繁体教程区块因现有站点无对应页面而省略；若希望覆盖须另行批准新增 URL/翻译范围。
- GA4 与用户本地未提交改动重复，合并后用户可丢弃本地那份。
