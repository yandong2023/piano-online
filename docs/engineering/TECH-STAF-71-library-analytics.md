# STAF-71 曲库埋点技术方案

对应 PRD v1（2026-11-06），覆盖 AC-1 至 AC-5；线上收数和报表属于发布后验收。

## 方案

选择在现有筛选回调和链接监听器内调用既有 gtag：直接使用实际可见卡片计算数量和序号，沿用页面语言，beacon 发出跳转事件，不拦截跳转。备选方案是独立 DOM 观察器/全局点击委托：需要反推筛选结果和动作来源，容易重复计数，故不采用。搜索 800ms 防抖，发送前去空白、折叠空格、识别邮箱/电话并替换，再截断至 60 字符；筛选本身不改变。重置取消待发搜索，合法深链单独上报。

## 影响面

无接口、数据迁移、权限、多租户、异步任务或服务端缓存改动；GA4 增加三种事件和参数，搜索输入涉及隐私，使用形态匹配脱敏，无法保证识别所有个人信息。浏览器脚本使用独立版本参数更新缓存；既有 GA loader/config 不变。生成器只给曲库卡片添加 song id；相关教程维持原链接。

## 变更清单

- `js/library-browser.js`：筛选、深链、搜索、歌曲点击上报。
- `js/song-page.js`：相关教程点击上报。
- `scripts/render-song-pages.mjs`：曲库卡片 ID 与独立脚本版本。
- `tests/song-library.test.mjs`：事件、空态、搜索与隐私回归。

## 验证

AC-1：本地测试检查事件参数，生产部署后以 DebugView 检查七种动作与连续五次点击，实时收数不能用本地模拟代替。AC-2：`npm run test:songs` 与三语人工回归；AC-3：`npm test`、两次 `npm run build` 文件对比及 sitemap URL 集合对比；AC-4：上线 48 小时后注册所需 GA4 自定义维度并运行两张探索表；AC-5：检查 diff 和 URL 集合。边界包括无 gtag、0 结果、长词、邮箱/手机号、非法深链、点击跳转。

## 上线与回滚

按发布决策合并功能分支并部署；无新增开关或数据迁移。回滚功能提交（`git revert <功能提交SHA>`）并重新部署，已采集 GA4 数据不会自动删除。部署后检查脚本版本和 GA4 收数；维度注册及其生效时间由 GA4 管理方确认。

## 风险和未知

beacon 不能保证所有跳转事件到达；GA4 维度数量、保留名及权限尚未核实，AC-4 依赖后台配置。搜索脱敏基于模式，不保证覆盖任意个人信息；生产验证会产生真实数据，执行时间按发布决策确定。原 issue 的 357 条 sitemap 是旧基线，PRD 记录现行为 369 条，仍需保持 URL 集合不变。
